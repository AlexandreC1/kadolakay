# Local encryption and recovery operations

All commands run from the Bayou repository. Never print keys/tokens, paste them into chat or commit .env/database exports. Test against a disposable loopback database ending_test first.

1. Run npm run security:setup. It adds a random32 byte DATA_ENCRYPTION_KEY to ignored .env without printing or replacing an existing key. Keep a separate secure copy; encrypted records and backups cannot be recovered without it. Supply the same key through the future host's secret manager. DATA_ENCRYPTION_PREVIOUS_KEYS supports explicitly retained old keys for reading during rotation.
2. Run npm run security:migrate-tokens for a dry run. Before deploying the encrypted adapter to a database with historical OAuth links, use npm run security:migrate-tokens -- --apply on an approved, backed-up target. It walks100 accounts at a time, binds encryption to user/provider/account/field, avoids overwriting concurrently changed tokens and prints counts only. Re-run the dry run to confirm no plaintext remains. This migrates provider tokens, not every encrypted field for key rotation.
3. Apply the reviewed migrations with prisma migrate deploy and generate the client. Deployment invalidates legacy cookies lacking a DeviceSession ID; users sign in again through their existing provider. No auth bypass or provider credentials are shipped for review.
4. Administrators visit /security within10 minutes of fresh sign-in, enroll on that same browser, confirm a real authenticator code and retain the ten one-use recovery codes. Setup expires in10 minutes; administrator verification expires in15 minutes. Recovery codes verify a browser once. Loss of both authenticator and all recovery codes requires a separately authorized operator recovery procedure; there is no public reset shortcut.
5. Set POSTGRES_BIN to the installed PostgreSQL binary directory if it is not on PATH. Run npm run backup:create -- /absolute/private/output.backup.enc. Output is exclusively created (no overwrite), streamed and encrypted with authenticated AES256GCM. Credentials are passed to PostgreSQL through environment variables, not command-line URLs. Remote backups default to verify-full TLS unless an explicit connection sslmode is supplied.
6. Create a new empty loopback database whose name ends_test, set DATABASE_URL to it, then run npm run backup:restore-test -- /absolute/private/output.backup.enc. The command refuses nonlocal/non-test/nonempty targets. It authenticates the complete backup before restoring, uses a single transaction and preserves schema constraints/triggers. Check row counts, migrations and immutable audit behavior afterward. Do not target the owner's original DB.

This is a local recovery tool, not managed retention, offsite custody, automatic alerts or a production disaster-recovery claim. Use a least-privileged application DB role on the host; operator migrations/backups need separately scoped credentials. Never configure production with the disposable trust-authenticated local PostgreSQL cluster.
